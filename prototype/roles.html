角色与权限设计（RBAC + 组织数据域 + 监管关系）

面向真实销售组织：总裁 / 运营经理 / 销售部经理 / 销售主管 / 小组组长 / 销售员 / 销售助理。权限由三层控制——① 功能权限（能用哪些功能）；② 数据范围（能看谁的数据，按组织上下级树）；③ 监管关系（纵向上下级 + 横向运营监管 + 审批链）。

数据范围模型（行级数据权限）

基于组织树的下属集合自动计算可见数据
👤

本人域

仅本人名下客户与业绩（销售员、销售助理默认）。

👥

本组域

组长可见全组组员数据（含本人）。

🏢

本部门域

主管/经理可见下辖所有组、销售的数据。

🌐

全公司域

总裁全权；运营经理只读监管 + 配置。

🔎
行级权限规则：可见客户集合 = 客户.归属销售 ∈ 当前用户的下属销售集合（含自身，按组织树递归）。上级自动可见下级全部数据（数据继承）；同级之间默认不可见。字段级：成本价、挂牌价、供应商货源等敏感字段仅经理及以上可见/导出。

5

监管与被监管关系

纵向监管（上下级）

数据继承
  • 上级自动可见下级全部客户、业绩、跟进达标率
  • 组长监管组员、主管监管组、经理监管部门、总裁监管全局
  • 下派任务、审批分配/回收、验收跟进结果
  • 下属操作全程留痕，对上级透明

横向监管（运营经理）

不占业务
  • 不在业务上下级链，独立监管职能
  • 全公司业务数据只读，不可抢客户、不改业绩
  • 负责规则/阈值配置、算力成本与用量监管
  • 数据异常、违规操作预警上报总裁

销售助理（代理权限）

继承范围
  • 无独立数据域，继承所辅助对象的可见范围
  • 可代录入跟进记录、代查询、整理报表
  • 不可审批、不可配置、无业绩归属
  • 代操作同样留痕（标注"代 XX 操作"）

7

权限模型技术实现

🧩

RBAC 角色-权限

角色绑定功能权限点(菜单/按钮/接口)，用户绑定角色，支持一人多角色。

🌳

组织树数据域

行级权限=归属销售∈下属集合(递归)；每次查询自动注入数据域过滤条件。

🔒

字段级权限

成本价/挂牌价/货源等敏感字段按角色脱敏或隐藏，导出同步受控。

📝

操作审计

分配/回收/授信/配置/导出/AI调用全程留痕，可追溯，满足集团审计。

🔐
落地要点：① 数据范围随组织架构调整自动生效，无需逐人配置；② 客户"我的客户""跟进分配""员工画像"等页面均按登录角色的数据域过滤展示；③ 敏感操作走分级审批 + 审计；④ 运营经理与业务链解耦，实现"监管而不干预业务、不抢客户业绩"。
